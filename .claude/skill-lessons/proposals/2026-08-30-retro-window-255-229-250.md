## P1 — `gate-state count_edits`: on a branch with no upstream, measure the commit half against the head the previous cycle recorded

**Bar: 2 records, plus clause 3 (a skill contradicting its own gate helper).**
- #255: "`gate-state --count-edits` reported `edits=0` for a cycle with 9 unpushed commits, because the
  branch had no upstream at that point."
- #229: "reported edits=0 with 3 unpushed commits on a branch that had no upstream yet. Did not affect
  the outcome (I measured commits myself) but the field was not reporting what its description says."
- Clause 3: `harden`'s State section says `--count-edits` counts "uncommitted lines plus commits not yet
  pushed, **both halves**, because a cycle that commits its work has still changed something", while
  `gate-state`'s own `count_edits` docstring says "a branch with no upstream has nothing to compare
  against, so that half is zero rather than an error". The gate blocks on `edits > 0` and allows on 0, so
  a cycle whose whole output was committed reads 0 and the gate permits the stop — fail-open in the one
  direction the gate exists to close. Pre-PR `harden`, which is where `resolve-ticket` Step 7 runs it, is
  the configuration that has no upstream.

**Edit (mechanical, in `~/.claude/pipeline/gate-state`):** `harden-set` records `head` (current HEAD sha)
on the entry it writes. `count_edits` keeps the `@{u}..HEAD` path unchanged when an upstream resolves;
when it does not, it counts `<previously recorded head>..HEAD`.

- Why not `git rev-list --count HEAD --not --remotes`: that counts every commit of the run, so on a
  pre-PR branch the number never returns to zero and the gate would block every stop until a push. The
  hook's own header says a gate that wedges turns is worse than one that lets an early stop through.
- Why not prose: last window recorded two prose remedies for `gate-state`'s `--only` defect that reached
  no caller, and the mechanical override that closed it.
- Residue, named: the first `harden-set` on an upstreamless branch has no previous head, so its commit
  half stays 0. This is better than today in the later cycles and no worse in the first.
- `head` is documented in prose only, not in the skill's state-file JSON example — the linter's
  `state_fields_vs_gate` check compares that example against `*gate*.sh`, and the reader of this field is
  `gate-state` itself, not the Stop hook.

**Prunes:** the docstring sentence "a branch with no upstream has nothing to compare against, so that
half is zero rather than an error" — retired by these two measurements, deleted rather than reworded.
Net: helper +6 lines, skill +1 clause.
