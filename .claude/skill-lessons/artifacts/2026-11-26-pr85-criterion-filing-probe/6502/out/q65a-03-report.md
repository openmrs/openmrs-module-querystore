**Set aside:**
- **R3:** It only happens when the UPDATE fails. I already ruled that out in the thread for core's argon2: its hashes are at most 126 characters and the column holds 128. Also, the only core caller (`InitializationFilter`) doesn't log in inside an open transaction.

The guard is what stops that old password being written back. This is reasoned only, because checking it needs a MySQL server. The ticket also asks for this re-check.
