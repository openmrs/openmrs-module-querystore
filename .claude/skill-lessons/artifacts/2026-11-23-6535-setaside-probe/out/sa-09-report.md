I'm filing three of the four: R1 and R3 as questions, R2 as a non-blocking suggestion about tests. I'm setting R4 aside because it's a thread you already opened, and the fix you suggested there is at the head.

**R1 → question.** Read from the head: the private `read()` in `LocalStorageService` tries the current location first, but `purgeData()` still goes through `getPath()`, which prefers the legacy copy. The head's own Javadoc on `getPath()` says so. On master, reads and deletes both went through `getPath()`, so they hit the same file. Nothing in the PR rules out a key existing in both places. `BaseStorageService.newKey` accepts a `keySuffix` from the caller, and an admin could copy legacy files into the storage folder while migrating. The method says a defect that can be triggered but is unlikely goes in as a question naming the condition it needs. It can only be set aside once the condition is shown to be impossible, and I can't show that. Making reads prefer the legacy copy again would bring back the existence check this PR removes, so I'm asking about it rather than calling it blocking.

**R2 → suggestion, about tests only.** The exception change itself is not a finding:
- In TextHandler and BinaryDataHandler, a read error that isn't a missing file now becomes `APIException`. On master it fell through to `Assert.notNull` and surfaced as `IllegalArgumentException`. That follows ibacher's comment asking for an `APIException` that wraps the `IOException`, made on that same catch path at `bf4dd935`.
- In BinaryStreamHandler nothing changed: master's `catch (Exception e)` already threw `APIException`.
- What's left is that no test covers the new paths. A grep of all `*HandlerTest.java` files finds no `APIException` assertion. As a control, the same grep does find the `IllegalArgumentException` assertion in `BinaryStreamHandlerTest.java:77`. The new message key `Obs.error.while.trying.get.complex` also isn't used in any test.

That thread is outdated, so this goes in as a fresh comment on the head lines.

**R3 → question.** At the head, `LocalStorageService.getDataWithMetadata` reads through private helpers and never calls `getData`/`getMetadata`. `S3StorageService.getDataWithMetadata` does its own GetObject, and every bundled handler calls `getDataWithMetadata`. So a subclass that overrides `getData` is silently skipped, where master honoured it. Neither class is final, and `StorageServiceCondition` lets a module plug in its own storage type, so a subclass like that is possible. But there isn't one in this tree, and with the network closed I couldn't check modules. With no real caller I can name, it goes in as a question. It's the same kind of break as the `injectMissingMetadata` one you already raised.
