I'd file R1 as a question and R2 as a suggestion that covers only its missing tests. I'd set aside R3, which isn't a defect, and R4, which was already raised and has been fixed.

**R1: filed as a question.** On master, `getData` and `purgeData` both go through `getPath`, which tries the legacy location first. At the head, reads go through `read()` (`LocalStorageService.java`), which tries the current location first, while `purgeData` still uses `getPath`. The PR's own Javadoc on `getPath` says this split is deliberate. If both copies exist, a purge on master also leaves the current copy behind, so that part is not new. What is new is that reads now return the other copy. The reviewer's test showed this. It only happens when both copies exist, for example after an admin copies legacy files into the storage folder without deleting the originals. That can happen, so the method says to ask rather than drop it. The behaviour changes silently and no test pins either order.

**R2: filed as a suggestion, for the tests only.** The switch to `APIException` is what ibacher asked for in thread 3990887402: "throw an APIException wrapping the IOException". So the exception change itself isn't something to raise.
- In `BinaryStreamHandler`, master already caught `Exception` and threw `APIException`, so nothing changed there.
- What remains is a coverage gap in `TextHandler` and `BinaryDataHandler`. The only exception assertion in the three handler tests is `BinaryStreamHandlerTest.java:77` (`IllegalArgumentException`). Removing either new `throw new APIException` would leave every test passing.
- ibacher's thread is outdated, so this goes as a fresh comment on the current lines, linking to it.

**R3: set aside.** A subclass overriding `getData` was never a documented route for other methods. The ticket asks for one combined data-and-metadata read in the backend. Sending it through the public `getData` would put back the separate path lookup and metadata calls the ticket removes. Custom `StorageService` implementations still get the interface default, which does call `getData` and `getMetadata`. Nothing in this repository extends `LocalStorageService` or `S3StorageService` except a test helper.

**R4: set aside.** You raised it on 2026-11-09 (comment 4512249216). The author applied your `@Deprecated(since = "3.0.0")` suggestion word for word (`AbstractHandler.java`, lines 152–158). No production code calls the two-argument overload any more. Under the method, a real fix gets no reply.
