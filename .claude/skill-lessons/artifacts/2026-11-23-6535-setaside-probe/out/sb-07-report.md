**R1 (both copies exist; read and purge pick different ones): set aside.** No code path writes the same key to both locations. `saveData` always creates a fresh key in the storage dir (timestamp plus 8 random characters, `BaseStorageService.newKey`), while legacy files keep their old names. Even when both copies are planted by hand, master doesn't do better. On master, `purgeData` deletes the legacy copy through `getPath`, and the next read's `getPath` finds no legacy file and returns the current copy. So the obs is still readable after a purge on master as well. I worked this out by reading master's `LocalStorageService` against the head version; I didn't run it. The only new effect is which copy gets served before the purge, which matters only if the two copies differ. Since I can't name a real way to reach that, it doesn't meet the bar for a comment.
