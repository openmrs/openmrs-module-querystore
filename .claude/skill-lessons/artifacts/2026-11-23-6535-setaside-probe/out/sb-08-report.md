R1 and R2 get filed, R1 as a question and R2 as a suggestion. R3 and R4 are set aside.

**R1 is filed as a question.** On master, `getPath()` checks the legacy location first for both reads and deletes. At this head, `read()` tries the storage dir first, but `purgeData()` still goes through `getPath()`, so deletes still prefer the legacy copy (`api/src/main/java/org/openmrs/api/storage/LocalStorageService.java`, `read` and `getPath`). Both copies only exist if something copied legacy files into the storage dir without removing them. An upgrade can leave data like that. I can't rule it out from the code, so the method says to ask rather than block. The comment names the condition: in that case reads change content compared with master, and a purge leaves the storage-dir copy behind.

**R2 is filed as a suggestion, and only its test-coverage half.** The switch from `IllegalArgumentException` to `APIException` is what ibacher asked for in thread 3990887402 ("throw an APIException wrapping the IOException"), so that half is not raised. `BinaryStreamHandler` already wrapped these errors in `APIException` on master, so it hasn't changed. The missing test is real. I removed the new `throw new APIException(...)` from both `TextHandler` and `BinaryDataHandler` and ran `TextHandlerTest`, `BinaryDataHandlerTest`, `BinaryStreamHandlerTest` and `AbstractHandlerTest` offline: 22 tests ran, 0 failed, exit 0. No handler test feeds in a non-missing `IOException` (a grep for `thenThrow|doThrow|new IOException|FileSystemException` finds nothing in the handler tests, and a control search for `getDataWithMetadata` does find them). So handlers could start swallowing storage errors again with every test green. That split was added after greptile's "Fallback masks storage failures" comment.

**R3 is set aside.** Nothing in the tree subclasses `LocalStorageService` or `S3StorageService` outside tests, and I can't name a downstream one. Other storage implementations get the interface's default `getDataWithMetadata`, which still calls their own `getData`.

**R4 is set aside.** I raised it already at this head (thread 4512249216). The author applied the suggested `@Deprecated(since = "3.0.0")` in 2e892b7, and it is in the head diff. Per Step 1, a fix that landed gets no comment.
