I'm filing R2 as a suggestion and setting aside R1, R3 and R4. I checked each against the head code and the review threads; no build was run, and the working tree is clean.

- **R2, filed as a suggestion.** The switch from `IllegalArgumentException` to `APIException` is not itself a finding. ibacher asked for it ("throw an APIException wrapping the IOException", RC 3990887402). But no test covers it: `git grep` over `api/src/test/java/org/openmrs/obs/` finds only `IllegalArgumentException` asserted for the missing-file case (`BinaryStreamHandlerTest.java:77`). If the new `catch (IOException e) { …; throw new APIException(…) }` branches in `TextHandler`, `BinaryDataHandler` and `BinaryStreamHandler` went back to log-and-continue, every test would still pass. A storage failure would then be reported as missing data again, which is the problem greptile's still-unanswered "Fallback masks storage failures" thread was about.
- **R1, set aside.** Nothing in the tree writes the same key to both the current and the legacy location. The only legacy handling outside `LocalStorageService` is the obs-dir prefix in `AbstractHandler.parseDataKey`. Even if both copies existed, master also deletes the legacy copy through `getPath` and then reads the current one. So "the data can still be read after a purge" behaves the same on master. The PR documents the read-current, delete-legacy split in `getPath`'s Javadoc.
- **R3, set aside.** The bypass comes from the shape ibacher asked for: shared private internals called directly (RC 3990739410, `getDataInternal(path)`). Reopening that needs a real subclass that overrides `getData`. There is none in the tree, and I can't name one outside it. Modules that implement `StorageService` themselves still get the interface's default, which calls `getData` and `getMetadata`.
- **R4, set aside.** It is already an open thread of yours (RC 4512249216). The author applied your deprecation suggestion in 2e892b7, and `AbstractHandler.java:152-158` at the head carries `@Deprecated(since = "3.0.0")` with a pointer to the three-argument overload. Under the method, a fix that holds gets no comment.
