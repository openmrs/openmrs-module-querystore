**Evidence I ran (scratch folders deleted, `git status --porcelain` is empty)**
- **The `Pair` order.** I compiled master's own `Pair.java` and commons-lang3 3.18.0 (the version core 2.8.0 ships) and grouped some rows with the PR's own `groupingBy` expression.
  - One store with one item: the same order on both (the control).
  - One store with items 1 to 5: master gives `1,2,3,4,5`, the head gives `1,3,2,5,4`.
  - Store 3 with items 1 to 10: master gives `3,4,…,10,1,2`, the head gives `3,2,1,7,6,5,4,10,9,8`. That is exactly what draft A said.
- **Why that changes alerts.** I read `processAlerts` top to bottom (`StockBatchExpiryJob.java:183`). It walks that map in order with `maxAlerts = 4` per user. Every batch it alerts goes into `batchNumbersNotified`, which sets the expiry notification date (`:141`). So at one store, item 4's batch loses its alert and item 5's gets one.
- **S3's shorter test string.** I ran the regex from before #76 (`73d9723^`) on a JVM with the default stack size. The 1,000-repetition control matches; 50,000 and 100,000 repetitions both overflow the stack. The current regex matches all three. So the test still catches the overflow at 50,000.
- **What I did not verify:** I did not run the expiry job itself on a server.

**Decisions**
- **S1 (test doesn't reach production code):** Greptile already raised this. The author answered by sharing `QUANTITY_FORMAT`, and the maintainer approved after that reply. What is left untested is 9 identical one-liners, all visible in the diff.
- **S2 (repeated `DecimalFormat` call):** the ticket asked to replace `NumberFormatUtil` with standard formatting. A `formatQuantity` helper would bring that utility back, and with one shared constant the 9 copies can't drift apart.
- **S3 (test placement and length):** 50,000 repetitions still overflow the old regex, and the package and class name are cosmetic.
- **S4 (tests "before swapping anything"):** this is about how the description words the commit order. The base and head use the same patterns and the same regex byte for byte, so the pins hold, and there is no code to change.
- **S6 (import position, anonymous classes):** each import replaces the `Action2` import on the same line, and the anonymous classes have the same shape as the ones they replace. That keeps the diff mechanical, and the formatter enforces neither point.
- **S7 (stale classes without `clean`):** any deleted class behaves this way in Maven. CI and the PR's checklist both build with `clean`.
- **S8 (locale read on every call):** the output only differs if something changes the JVM's default locale after the first format call, and then the head follows the current locale.
